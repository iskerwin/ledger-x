## 核心不变量

账务来源为 Beancount 文本，不建立另一份账务数据库。共享设置写 ledger-x.json；本机偏好/草稿/队列与缓存保存在本机，凭据在 Keychain。草稿、恢复文件、浏览条件与后台结果按账本隔离；回调须核对账本标识、文件版本和请求令牌。

交易输出为 draftText → formatTxn → orderedPostings，经 makeOps/applyOps 和提交前 checks 写入，不能在界面手拼。账户、金额、汇率、费用规则见 02。

## 记账与模式转换

- Drafts.swift：草稿、交易类型、生成、校验、字段与持久化兼容。
- EditorMode.swift：convertingEditor 用实际文本转换，再用 sameTxn 验证往返；失败保留输入。
- Editing.swift / EntryLocator.swift：已有交易读回与重新定位；多笔相同原文只改仍匹配原锚点的一笔，歧义不猜。
- QuickAddView、AddView：共享 Store 草稿，切换成功后才改模式；源文本完成走 applyDraftSource。
- RateSheet：局部 working/candidate；FeeFields 只改会话，完成一次写回，取消/下滑不应用。TransferFeeSheet 为定位费用区的兼容包装，不维护第二套保存状态。
- TransferFee.swift / ExpenseFee.swift：统一本金、费用、实扣/到账、银行报价保护和读回，sameTxn 兜底。

## 保存与同步调用链

Store.commit → 预检查 → 持久化队列 → onQueued（关闭已保存卡片）→ 本机 rebuild → 一次 saveConfirmation → requestSavedSync。校验失败不调用 onQueued；远端等待移出普通保存。waitForSavedSync 保护切账本、连接、刷新与清缓存。

检查可复用 before 账本，但只在文件全下载且正好匹配将推送队列与版本时；暂存/失败操作不混入。after 和安全检查不能省略。同步后文本未变且版本/队列匹配时才跳过重复 rebuild。

撤销先捕获前后文本，revertOps 后台比较；缺文件时不伪造撤销。SaveTiming 只记阶段耗时和数量，不记账户或文本。性能用虚构样本测量，不能仅以调用改写声称真机提速。

## 草稿与异步状态

QuickAddView 输入状态不重建整个宫格。scheduleActiveDraft 更新内存，合并短时间连续写盘；后台编码返回前核对取消、账本和快照。关闭、明确保留、App 非活跃等边界立即刷盘。已有的草稿合并写盘时间属于持久化策略，不能作为新增固定延时掩盖状态问题的先例。

AccountPicker 搜索框在顶部 safeAreaInset，FocusState 只控制键盘，pending 只有完成时应用；稳定的辅助功能标识供 UI 测试定位。

## 导入与附件恢复

BillLoader 独立 actor 解析不可变账单，页面令牌/账本标识丢弃过期结果。ImportCheckpoint 保存源文件、映射、选择与进度，resumeImportChoices 重新查重；按日期索引匹配，并保留订单优先和每笔只匹配一次。

RecoveryFiles 在私有 Application Support/Recovery 以账本标识哈希分文件、原子写并使用文件保护。AttachmentUpload 保留二进制、源交易定位、固定路径/链接与阶段；二进制单独存为 attachment-<id> 恢复文件，任务列表只存元数据，Store.attachmentJobs 每个账本只从磁盘读一次后缓存在内存（视图每次重绘都会读取，列表含图片时会卡住主线程），旧版内嵌图片的列表在首次读取时先把图片移出、成功后才改写列表。AttachmentPathSheet 初始化接收现有路径，手动编辑标记先于名称变动写入；上传中和已创建任务后不刷新默认名。prepareAttachment 同步校验并持久化任务，再启动可取消的 uploadAttachment；确认页保存任务身份，attachmentTakenPaths 仅排除自己的恢复记录与确认已上传文件。uploadAttachment 抛出具体错误留在原页，恢复列表通过 retryAttachment 显示提示。网络请求前后与关联写入队列前检查取消，已经完成的文件写入先记录 uploaded；上传前持久化可选 uploadStarted，响应不确定后重试先读取比对字节；缺失任务拒绝复活，已有 document 需同时核对原交易、路径、日期、账户与链接；commit 的 cancellable 选项只由附件启用，写入队列后继续完成本机重建，不撤回已保存操作。先上传文件再提交关联，不宣称跨网络原子；失败保留副本，重试不重新生成路径。全局 committing 和业务局部 busy 防重复及切账本串写。

Documents.swift 的 documentFolder、preferredDocumentFileName、documentStoragePath、documentPayingAccount 决定目录/重名与付款账户；AccountDocumentSheet、AttachmentPathSheet 共用位置确认交互与 documentLocationIssue 的保存状态校验：busy 时不实时校验位置，成功关闭全程保持 busy，失败/取消后恢复编辑校验；AccountDocumentSheet 同时禁止 busy 时重算默认名，避免目录更新把本次写入误判为冲突或改动确认名称。撤回关联指令不删除上传文件。AttachmentDeletion.swift 处理「移除并删除文件」：先 readData 存 RecoveryFiles 副本，再 deleteDirective，记下对应的 ChangeRecord；finishAttachmentDeletions 在无待推送改动、无引用时按复制时的版本调用 backend.delete，每次同步成功后重试，同一时间只有一个运行（attachmentDeletionRun，结束时自行清空）；restoreDeletedAttachment 与 putBackDeletedFile 先等进行中的删除结束，再按存储的最新状态决定是否上传，不用调用方手里的旧副本；revert 先 restoreDeletedAttachment 上传副本再撤回文本；pruneDeletedAttachments 清理删除超过 30 天的副本；recoverDeletedAttachment 供「最近删除」使用：记录仍在 history 且未撤回时调用 revert，否则 putBackDeletedFile 上传副本并立即移除这条删除记录（不能再标为待删除：写回指令前若发生同步，内容相同的文件版本也相同，会被再次删除），然后用 DeletedAttachment.text 重建指令后 commit，失败只提示文件已恢复、记录未写回。FolderBackend 的附件版本是大小与修改时间，删除时按同样方式核对。

## 业务、报表与显示

reconcileDue 单次扫描按账户币种计算，reconciliationAgrees 拒绝无效非空余额。ReimbSheet 按币种选择，reimbursementTotal 不混币种。信用卡/订阅/报销/备用金/预算表单使用局部 busy、轻量字段快照和 protectUnsavedChanges；linkOps 可整批失败，不能提前关闭或用过期行号关联。

ControlStyle.swift 集中 AppSpacing、ControlLabelStyle、ActionRow；系统菜单/确认弹窗保留支持的系统样式。Sensitive 保护金额与图表可访问性，Haptics 统一偏好，RootView 遵守减少动态效果。

界面约定（新代码照此写，存量随触碰对齐）：

- 动效只用 `AppMotion` 三档：quick（点按的回应：筛选、选中）、standard（展开收起、换位置：月历、换月、滚动）、emphasized（值得注意的时刻：提示出现）。不写时长字面量，不为动画加固定延时。金额换值用 `rollingNumber`；换月标题用 `SlidingTitle`；展开箭头用 `TurningChevron` 原地旋转。
- 自绘的可点卡片、Chip、分类格用 `PressStyle`（按下 0.98 + 变淡，只影响绘制）；减少动态效果时不缩放。记一笔数字键盘不加按压缩放，保证连续输入位置稳定。
- 动画只挂在发生变化的控件上（`.animation(_, value:)`），不包在整个列表、Store 或交易数组的修改外面；筛选结果直接切换。
- 切换时高度要稳定的卡片：同一位置轮换内容用 `concealed` 叠放，三栏数字用 `FigureRow`（等宽、不缩小、放不下改竖排）。
- 触感：`Haptics.selection` 用于点选和切换（分类、类型、子分类），`success` 用于保存成功、`selection` 用于暂存本机，二者都随底部提示出现（`show(feedback:)`），`warning` 用于需要你确认的时刻（删除确认、提交前检查发现问题、关闭时有未保存的修改），`error` 用于保存被拦下或失败。一次点击只触发一次。
- 弹层三档：选择器（选账户、币种、标签、图标、关联、当天明细）用 `pickerSheet()`，半屏打开、显示拖动条、可拉到全屏，带搜索的在开始输入时自动拉到全屏；要填写的表单和要阅读的内容全高（系统默认，曾指定过别的高度处写 `formSheet()`）。记一笔的日期弹层需要 500pt，是唯一的定高例外。
- 共用组件：页面底部主按钮 `primaryButton()`、工具栏保存 `SaveLabel`、按钮忙碌态 `BusyLabel`、整页加载 `PageLoading`（概览、明细用灰色骨架 `PageSkeleton`；账本加载中即显示各标签页，只有加载失败才换成整屏 `LoadingView`）、空列表加按钮 `EmptyAdd`；动效修饰：月份条横滑 `monthSwipe`、被拦抖动 `shake`、列表增删 `listChanges`、行放大进详情 `zoomSource` / `zoomed`（iOS 18），都遵守减少动态效果；全部列表搜索用 `appSearchable`（选账户自带的搜索框用 `searchFieldLook` 画成同样外观）；圆角用 `AppRadius`（card 22 / panel 14 / control 12 / tile 8 / mini 4）。
- 带标题的 Section header 用 `.textCase(nil)`，保持中文与科目名原样。
- 只有图标的按钮必须有 `accessibilityLabel`；勾选类列表的行加 `.isSelected`。新的界面文字补 `Ledger/en.json`，`tools/check_project.py` 会检查缺译与不再使用的译文。系统直接读取、不经 `LS` 的文字——快捷指令的名称、说明、参数与 Siri 短语、权限说明——英文在 `Ledger/Localizable.xcstrings`、`AppShortcuts.xcstrings`、`InfoPlist.xcstrings`，跟随 iPhone 语言，同样由该脚本检查；界面里不要用会被 SwiftUI 查表的中文字面量（`Text("…")`），一律经 `LS`。信用卡卡片的 ListRowBottomShadowClamp 仅处理该单元格投影。

## 后端与备份边界

GitHub、GitLab、Gitea/Forgejo 尽可能将批量文本合并一次提交；文件夹/WebDAV 不保证跨文件原子。附件二进制上传与交易文本关联分阶段。备份当前可读取账本/配置/BQL 文本及队列效果，未覆盖所有附件或私有恢复文件，不写成所有文件的完整备份。

## 工程与外部依赖

XcodeGen 生成 Ledger.xcodeproj，包 LedgerKit 为本地依赖，Swift 工具版本 5.9；工程 Swift 5 模式。构建、测试与发布都在本机执行（见 04）。测试与 IPA 内置演示固定到同一公开提交；App 运行时可检查演示数据更新。所有命令以仓库文件为准。

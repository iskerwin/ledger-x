# 02 记账与数据规范（必须遵守）

> App 写进账本的**每一笔**都必须符合本规则，而且必须经过 LedgerKit 现有的格式化函数 `formatTxn`（在 `LedgerKit/Sources/LedgerKit/Format.swift`）。不要在表单或界面里自己拼接、排序分录。
> 本篇是本项目的强制数据契约，定义用户确认的记账要求，不读取私人账本完成核对。规则和代码不一致时先报告，不自行更改规则。

## 1. 名词

- **交易**：标题行加若干分录行。标题行格式为 `日期 * "收付款方" "说明" #标签 ^链接`。
- **分录（posting）**：一行一个账户和金额。一笔交易里所有分录加起来要平衡（按币种和汇率换算后合计为 0）。
- **元数据（meta）**：`键: 值`。交易的元数据缩进 2 格，写在标题行下面；分录的元数据缩进 4 格，写在该分录下面。

## 2. 格式

- 分录缩进 2 个空格。金额右对齐，**数字的最后一位落在第 59 列**（代码里是 `NUM_END = 59`），后面空一格再写币种。
- 同一个文件里按日期从早到晚排列，交易之间空一行。同一天内的先后顺序就是文件里的顺序，不加时间字段。

## 3. 分录顺序

由 `orderedPostings` 统一执行：

1. 先写 **支出 / 收入 / 权益**（Expenses / Income / Equity）。这几行之间保持原来的先后顺序。
2. 再写**收钱的**资产或负债账户，即金额 ≥ 0 的行。
3. 最后写**付钱的**资产或负债账户，即金额 < 0 的行。

补充说明：

- 没写金额的那一行，按 Beancount 会给它补上的正负号来排。如果推断不出正负（比如金额是算式、有两行都没写金额、涉及多币种），就保持原来的顺序。
- 举例：
  - 消费：`支出 → 卡`
  - 转账：`转入 → 转出`
  - 换汇：`买入币种 → 卖出币种`
  - 手续费：属于支出，所以**自动排在最前面**
- 顺序用于文本一致性，不借规范整理改动用户账本。
- 测试：`PostingOrderTests`。

## 4. 账户

- **手续费**：`Expenses:Fee:Bank`。单独占一行分录。
- **返现 / 优惠**：`Income:Rewards`。
- **往来账户**：
  - 报销应收：`Assets:Receivable:Reimbursement`
  - 公司往来：`Assets:Receivable:Employer`
  - 个人往来：`Assets:Receivable:Personal`，每一行分录都要写 `person:`
  - 向别人借款：`Liabilities:Loan:<拼音>`
- **账户的元数据**（写在 open 指令下）：
  - `name`：显示名
  - `statement_day`：核对日
  - `due_day`：还款日
  - `credit_limit`：信用额度
  - `min_payment_rate`：最低还款比例
  - `allow_negative`：是否允许负余额

## 5. 标签与写法

| 情形 | 写法 |
| --- | --- |
| 转账 `#transfer` | 收付款方写 `"Transfer"`，说明写 `"转出 -> 转入"`，例如 `"WeChatPay -> BOC"`。App 用这句说明来学习账户简称。 |
| 换汇 `#fx` | 两边币种不同时使用：可以是同一机构内换汇，也可以是跨账户转账时换了币种。<br>收付款方写**办理换汇的机构**，如 HSBC、Wise、ZABank、OKX。<br>说明写路线：跨账户写 `"BOC -> HSBC"`，同账户写 `"HKD <-> USD"`。 |
| 汇率元数据 | `exchange_rate: "1 GBP = 10.5791 HKD"`，**银行怎么写就怎么记**。两种方向都应保留，比如 `1 HKD = 0.1277 USD` 和 `1 GBP = 10.5791 HKD`。**不要统一改写方向**。 |
| 换汇金额 | 在**买入的那一行**用 `@@ 总额` 写明花了多少原币。 |
| 外币消费 | 照账单原样记成「标价币种 @ 扣款币种」，例如 `23.00 CNY @ 1.17912 HKD`。 |
| 手续费 | 单独一行 `Expenses:Fee:Bank`。按明确选择的扣费方式确定费用来源，不能一律额外增加转出扣款。 |
| 其他标签 | `#refund` 退款，配合 `^refund-…` 链接；`#reimbursed` 垫付；`#reimbursement` 报销回款；`#<事件>` 事件标签。 |
| 链接前缀 | `^refund-`、`^reimburse-`、`^float-`、`^salary-`、`^sub-`、`^doc-`。只能用英文字母、数字和 `- _ / .`，商户名用拼音。 |
| 其他元数据 | `person:`、`category:`、`voucher:`、`order: "…"`（订单号必须加引号）、`topup: TRUE`、`subscription:`、`payslip_days`、`payslip_items`。 |

## 6. 虚构示例

以下日期、金额、商户和机构均为虚构，仅说明约定写法，不代表当前快捷表单支持全部情况。手续费与同账户换汇的交互范围见 [01](01-产品功能与交互.md)。示例不应代替自动化测试。

**转账带手续费**（手续费 → 转入 → 转出）

```beancount
2025-01-10 * "Transfer" "Wallet -> ExampleBank" #transfer
  Expenses:Fee:Bank                                    2.00 CNY
  Assets:Bank:ExampleBank                            200.00 CNY
  Assets:EWallet:ExampleWallet                      -202.00 CNY
```

**同账户换汇带手续费**（买入 GBP，以 HKD 计总价）

```beancount
2025-02-10 * "ExampleBank" "HKD <-> GBP" #fx
  exchange_rate: "1 GBP = 10.00000 HKD"
  Expenses:Fee:Bank                                    2.00 HKD
  Assets:Bank:ExampleBank                             30.00 GBP @@ 300.00 HKD
  Assets:Bank:ExampleBank                           -302.00 HKD
```

`@@ 300.00 HKD` 是换汇本金，手续费 2.00 HKD 另外记，转出合计 302.00 HKD。

**跨账户换汇**（没有手续费，保留银行报价方向）

```beancount
2025-03-10 * "ExampleBankB" "ExampleBankA -> ExampleBankB" #fx
  exchange_rate: "1 CNY = 1.10000 HKD"
  Assets:Bank:ExampleBankB                           220.00 HKD @@ 200.00 CNY
  Assets:Bank:ExampleBankA                          -200.00 CNY
```

**外币消费带返现**（标价币种 @ 扣款币种，返现记收入）

```beancount
2025-04-10 * "示例商户" "日用品"
  Expenses:Shopping:Personal                          20.00 CNY @ 1.20000 HKD
  Income:Rewards                                      -0.50 HKD
  Assets:Bank:ExampleBank                              0.50 HKD
  Assets:Bank:ExampleBank                            -24.00 HKD
```

**外币消费带手续费**

```beancount
2025-05-10 * "示例商户" "文具"
  Expenses:Shopping:Personal                         100.00 CNY @ 1.20000 HKD
  Expenses:Fee:Bank                                    2.00 CNY @ 1.20000 HKD
  Assets:Bank:ExampleBank                           -122.40 HKD
```

## 7. 文件位置与 ledger-x.json

**写入位置由配置和现有账本共同决定，以下路径不是所有用户的固定默认值：**

| 内容 | 配置与自动判断 |
| --- | --- |
| 交易 | 优先使用 `ledger-x.json` 的文件规则；否则从最新年份的交易分布推断，例如 `journals/{year}.bean` |
| 开户 / 关户、余额断言、价格等 | 配置优先；未配置时通常写入已有同类指令较多的文件，例如 `accounts/balance.bean` 或 `prices.bean` |
| 订阅 | 使用配置或订阅文件规则，常见位置为 `subscriptions.bean` |
| 我的查询 | `queries/custom.bql`；已有其他 `.bql` 和 `query` 指令也可读取 |

具体判断见 `RepoLayout.detect`、`fileFor` 和 `makeOps`。账户分流规则、年份模板、新文件的 include 需要一并考虑。

**`ledger-x.json`**：所有设备共用的 App 设置，放在账本仓库里。

- `files`、`rules`：改变上面的写入位置。
- 其他字段：`slugs`、`payslips`、`scan_cards`、`default_funding`、`default_currency`、`large_expense`、`searches` 等。

**配置指令的边界：**常规记账表单不提供 `option`、`plugin` 的专门配置入口。App 为新文件生成记录时，可以自动向主文件补充 `include`；不能写成“App 永远不写 include”。源文件编辑是另外的高级入口，应说明其影响。

## 8. 对开发者的硬性要求

1. 新交易类型、新字段，最终都必须通过 `formatTxn` 输出。不要绕开 `orderedPostings` 自己排序。
2. 新加的表单字段必须能从已有交易**读回来**（`editDraft` / `sameTxn` 往返一致），否则这类交易只能退回编辑源文本。
3. 写入前会在本机按改后的账本重算一遍，检查平衡、断言、余额不足和信用额度；之后通过队列成批写入。支持的 Git 后端尽量合成一次提交；文件夹和 WebDAV 不保证跨文件原子写入。不要绕过预检查。
4. 改汇率或报表逻辑后，必须核对现有测试及 Beancount 对照。本机验证（`python3 tools/ship.py test`）执行 `tools/fixtures/check_reports.py`，见 04。脚本默认允许绝对差值不超过 0.01；如修改金额逻辑，应检查具体测试与比较范围，不笼统承诺每个路径都已对照。
5. 永远不要修改 `iskerwin/ledger`。

## 9. 汇率与手续费字段语义

- 转出金额是否含费由面板明确选择。`included`：原币总扣款含费，`@@` 为总扣款减手续费；`added`：本金外另扣费；`deducted`：从兑换所得目标货币扣费，实际到账填写净额；`separate`：在指定账户、币种单独支付。
- `@@` 只表示参与兑换的原币本金。费用单列 `Expenses:Fee:Bank`，仍通过 `formatTxn` / `orderedPostings` 排序。
- 目标币种扣费：买入正分录记录毛额并带 `@@`，另以目标账户负分录扣费；这两行合计等于净到账。不通过混算币种或调整银行报价来平衡。
- 已选扣费方式以 `fee_mode` 字符串元数据保存，单独支付另写 `fee_account`。编辑、复制与模式往返通过分录和元数据恢复，并以 `sameTxn` 检查。无 fee_mode 标记的交易按额外扣费解释，无法无损表示时保留分录/源文本。
- 草稿缺少可选字段 `feeMode` / `feeFunding` 时照常解码，按额外扣费解释。空费用不产生费用分录或模式元数据。
- 内扣费用必须使用被扣金额币种，且原币内扣费用必须小于总转出；扣费账户和费用科目需支持费用币种。
- 目标币种须符合转入账户限制；同账户换汇必须不同币种。银行报价与实际金额各自保留，报价不代替分录平衡校验。

虚构内扣样例（与真实账单无关）：

```beancount
2025-02-01 * "ExampleBank" "HKD <-> GBP" #fx
  exchange_rate: "1 HKD = 0.125310 GBP"
  fee_mode: "included"
  Expenses:Fee:Bank  0.20 HKD
  Assets:Bank:Example  10.00 GBP @@ 79.80 HKD
  Assets:Bank:Example  -80.00 HKD
```

## 10. 支出手续费（统一面板）

支出商品金额与手续费分开：账单金额/换算金额不含手续费，合计扣款在面板另行显示。手续费单列 `Expenses:Fee:Bank`，仍由 `draftText` → `formatTxn` / `orderedPostings` 统一生成和排序。

- 费用以账单币种列示、由原付款账户支付时，费用行使用本次商品换算基础的 `@`；若精度无法准确还原到分，则使用精确 `@@`，付款账户按付款币种合并费用扣款。
- 费用已用付款币种列示时，直接加到该账户扣款，不再次换算。
- 其他账户或第三种币种单独支付时，指定账户、币种直接扣费，不隐式增加另一笔换汇。
- 普通支出只提供另付（`added`）和单独支付（`separate`），不套用转账的转出内含、兑换所得内扣概念。沿用可选 `fee_mode` / `fee_account` 标记；无 fee_mode 标记的费用经完整往返校验后仍按原分录保留。
- 可选草稿字段复用既有费用字段，未填费用不新增分录或元数据。编辑、复制和模式往返必须通过 `sameTxn`；无法完整表示时使用分录/源文本。

虚构例：商品 10 GBP，按 1 GBP = 9 HKD 换算；费用 1 GBP，则商品扣款 90 HKD、费用扣款 9 HKD、原账户合计扣款 99 HKD。商品与费用各自用 GBP 列示并带 `@ 9 HKD`，不把 11 GBP 当成商品本金。

## 11. 账户票据的文件位置

账户票据和交易附件都放在 `documents/<文件夹>/<文件夹>_<YYYYMMDD>[_n].<扩展名>`，只嵌套一层，文件夹名小写。文件夹和文件名规则如下。

交易附件默认放在独立的 `documents/receipts/`（`transactionAttachmentFolder`），不和账户的对账单混在机构文件夹里；用户仍可改选其他文件夹。区分交易附件和账户票据看链接，不看文件夹：与某笔交易共用链接的 `document` 是交易附件（`transactionAttachments`），列在账户页统一的「交易附件」里，不进各账户的票据列表；其余是账户票据。早先存进机构文件夹的交易附件因此无需移动、照样归类。附件与交易所在的 .bean 不在同一目录由相对路径表达，Beancount 按指令所在文件解析并检查文件存在。

账户票据的文件夹（`documentFolder`）：

- 资产或负债至少三段时，用第三段。虚构账户 `Assets:Bank:DemoBank:Cash` 与 `Liabilities:CreditCard:DemoBank` 都是 `demobank`，同一机构的银行卡和信用卡共用文件夹。
- 资产或负债只有两段时，用最后一段，例如 `Assets:Cash` → `cash`。
- 支出、收入、权益等其他账户用最后一段，例如 `Expenses:Food:Demo` → `demo`。不能做文件夹名的段（空、含斜线、`.`、`..`）不自动采用，要用户另选。

文件名默认是文件夹加 `YYYYMMDD`。对照当前账本目录 `Store.tree.files`：同名已存在就用 `_1`、`_2`，中间空号会先用较小的号；文件名和扩展名一起按完整路径比较，不同文件夹或扩展名不冲突。确认附件打开即使用当前账本目录与其他恢复任务的路径计算默认名；手动改过后刷新不会重置，保存时固定用户确认的路径。重试只排除本次任务自己的恢复记录、其已上传或请求结果不确定的文件及已核实属于本任务的关联，仍检查其他任务和文件。扩展名只保留字母和数字并改为小写。用户可以改文件夹和文件名的主干，不能改扩展名，也不能写入空名字、斜线、引号、换行或 `.` / `..`。

`document` 指令写法：`日期 document 账户 "相对路径"`。账户票据的账户是打开票据的那个账户。交易附件的账户是付款账户：资产或负债里金额为负的一方；转账就是转出的一方。没有往外付钱的一方时（收入、退回到账户），用第一个资产或负债账户。路径按指令所在文件换成相对路径，交易用 `^doc-` 链接关联。写入前先检查，可在最近改动中撤回指令；撤回添加不会删除已上传的文件。失败后的重试继续用确认时的路径和链接。

删除交易附件或账户票据时有两个选择，两种附件规则相同：「只移除引用」只删 `document` 指令，文件留在存储里；「移除并删除文件」在仍有其他 `document` 指向同一文件（`documentReferences`）时只移除引用并提示保留。否则先把文件下载到本机私有恢复目录（下载或保存失败则不做任何改动），再移除指令；指令的移除推送到存储、且没有记录重新指向该文件后，才按复制时的版本删除文件，存储里的文件已被改动则不删。本机副本（`DeletedAttachment`，同时保存被删指令的原文和所在文件）在文件删除后保留 30 天；在最近改动撤回这次删除时先用副本重新上传文件，上传失败则不撤回。账户页「交易附件」底部的「最近删除」列出这些副本（附件与对账单都在内），「恢复」在最近改动仍保留那条记录时走撤回；记录已不在最近 100 条里时，先上传副本，再按原指令的日期、账户、链接把指令写回（路径按写入的文件换成相对路径）。

附件目录在各后端同时索引 documents 下的二进制文件名，用于查重，不改变账本文本解析。文件夹和 WebDAV 新附件仅创建，拒绝覆盖其他操作先占用的路径。恢复任务在上传前保留请求开始状态；请求结果不确定时，重试先比对已上传文件的完整字节，相同则继续关联，明确不存在才重传，不同内容或无法读取时保留恢复副本并报错。仅有相同路径不代表本任务已完成关联。

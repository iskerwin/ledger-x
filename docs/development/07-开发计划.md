# 07 开发计划

这是待选清单，不是承诺：每条由 Kerwin 选定后，再按 [AGENTS.md](../../AGENTS.md) 说明前后变化、确认范围，一件事一个分支。做完的条目从这里删掉，结果记在 CHANGELOG，不在这里记发布状态。

每条写明：现在什么样、做了以后看到什么、为什么值得做、工作量（小 / 中 / 大）、风险、建议（做 / 暂缓 / 不做）、依赖和验收方式。组内按性价比从高到低排。没量过的性能问题一律写「先测量」。

## 一、Mac 与手机的功能对齐

依据 01 功能清单和手机「使用指南」逐项对照 Mac 各页面（`LedgerMac/`）。Mac 已有：概览、明细（表格、排序、多选、修改原文）、账户（管理账户、核对余额）、报表、收付款方、年度回顾、预算（管理预算）、现金流预测、订阅（只能忽略）、报销、工资、事件、值得留意、BQL 查询、附件与对账单、同步与改动、记一笔窗口、多步撤销和重做、中英文。

### 1. Mac 订阅管理

- **现在**：Mac 订阅页只能看和忽略可能的订阅；新增、调价、暂停、恢复、取消、记一笔扣费只能在手机上做。
- **做了以后**：在 Mac 订阅页直接管理订阅，和手机写进账本的内容一致。
- **为什么**：订阅是常用页面，计算已在 LedgerKit（`Subscription.swift`），只缺 Mac 界面。
- 工作量：中。风险：低，写账走同一条 `prepareFolderSave` 路径。
- **建议：做。** 验收：Mac。

### 2. Mac 报销回款

- **现在**：Mac 报销页能看到「待回款」，但不能记回款。回款要回手机的「报销回款」去记，导出报销单也只有手机能做。
- **做了以后**：在 Mac 上勾选垫付、记回款（含币种），并能导出报销单。
- **为什么**：报销单常在电脑上整理和发出，Mac 更顺手。回款和导出的规则已在 LedgerKit（`ReimbReport.swift`、`Export.swift`）。
- 工作量：中。风险：低。
- **建议：做。** 验收：Mac。

### 3. Mac 批量编辑

- **现在**：Mac 明细表格已经能多选，但只能复制原文；批量改分类、账户、标签只能在手机上做。
- **做了以后**：在表格里选中多笔，右键批量修改。
- **为什么**：大屏多选最适合批量整理，这是 Mac 的天然优势。
- 工作量：中。风险：中，一次改多笔，靠现有提交前检查和撤销兜底。
- **建议：做。** 验收：Mac。

### 4. Mac 账单导入（CSV / XLSX）

- **现在**：只有手机能导入银行或支付平台账单。
- **做了以后**：在 Mac 上选文件、对应列、核对查重、确认入账；大屏核对几十上百行更轻松。
- **为什么**：解析、查重和导入恢复都在 LedgerKit（`Import.swift`、`Xlsx.swift`、`ImportRecovery.swift`），Mac 只需要界面和本机进度。
- 工作量：大。风险：中，导入进度要按账本隔离。
- **建议：做，排在 1–3 之后。** 验收：Mac。

### 5. Mac 投资持仓与更新价格

- **现在**：Mac 没有持仓页，也不能联网更新证券和外币价格。
- **做了以后**：Mac 账户里能看持仓和盈亏，并一键更新价格。
- **为什么**：有投资或外币账户时，净资产要靠最新价格才准确。
- 工作量：中。风险：低。依赖第 15 条（取价代码移进 LedgerKit）。
- **建议：做。** 验收：Mac。

### 6. Mac 分类管理与快捷卡片的本机偏好

- **现在**：Mac 不能改分类的图标、颜色和排序。快捷卡片也不读手机上设好的这些偏好，常用交易不能置顶，账户不显示卡号尾号（03 里写着「不做」）。
- **做了以后**：两端分类长得一样、顺序一样。
- **为什么**：两端看起来一致，就少一层困惑。
- 工作量：中。风险：低。这些偏好现在只存在手机本机、不进账本。要两端一致，就得写进 `ledger-x.json` 共享，这是数据契约的变化，要你单独确认。
- **建议：你先决定要不要共享，再做。**

### 7. Mac 同日顺序调整

- **现在**：同一天几笔交易的先后顺序只能在手机上调。
- **做了以后**：Mac 表格里可以拖动，或用右键上移、下移。
- 工作量：小到中。风险：低（手机的「调整当天顺序」在 `JournalView.swift`，排序规则在 LedgerKit `Format.swift`）。
- **建议：暂缓**，需要时再做。

### 8. Mac 使用指南

- **现在**：Mac App 里打不开使用指南。指南只在手机「设置」里，主要写手机操作，夹着几条 Mac 说明（管理预算、撤销等）。
- **做了以后**：Mac 的「帮助」菜单打开指南，按 Mac 的操作写（快捷键、撤销、表格、同步页），手机指南里的 Mac 条目移过去。
- 工作量：小到中。风险：无。
- **建议：做**，可以和 1–3 一起补。验收：Mac。

### 有意不同（建议不对齐）

| 手机有、Mac 没有 | 理由 |
| --- | --- |
| GitHub / GitLab / Gitea / WebDAV 连接、离线队列 | Mac 直接打开本机文件夹，用本机 git 同步，更简单可靠（见 03） |
| 面容 ID 锁、钥匙串里的卡片信息、卡面、提醒、快捷指令与 Siri | 都是手机平台功能；Mac 上随身支付卡信息的需求低 |
| 演示账本、新建空账本、多账本切换列表 | Mac 用「打开账本…」选文件夹即可；需要时可补「新建空账本」（小） |
| 明细三种行样式 | Mac 用表格，列宽已按内容排 |

Mac 独有的多步撤销重做、表格排序多选、git 差异页，手机已有对应做法（最近改动撤回、筛选、改动核对），不需要搬回手机。

## 二、两端共同的体验改进

### 9. Mac 版本发布与更新

- **现在**：Mac 版每次 main 有改动就自动替换 GitHub 上固定的 `mac` 预发布；构建号一直是 1。它不经过开发版、验收、转正流程，只做了仅限本机的签名，也没有更新提示。
- **做了以后**：Mac 和手机用同一个版本号和构建号，一起出开发版、一起验收、一起转正；Mac 上能看出自己是哪一版、有没有新版。
- **为什么**：现在没法确认手里的 Mac 版对应哪份源码，验收也对不上号。
- 工作量：中。风险：低（只改发布工具）。
- **建议：做，优先级高**，后面的 Mac 功能都受益。
- 06 要补一节 Mac 验收清单（见第 13 条）。

### 10. 去掉旧系统月历的回退开关

- **现在**：新月历 10 月 27 日上线时保留了「回退旧月历」的隐藏开关（`journal.glassCalendar`），说好只保留一个版本，现在已经过了好几个版本。
- **做了以后**：界面没有变化；少一套月历代码和对应测试，界面测试更快、更稳。
- 工作量：小。风险：低。
- **建议：做。** 验收：手机看一眼明细和订阅月历。

### 11. 曾提出但未合并的界面方向

- #127「界面改用暖米纸色，卡片加细线」和 #92「界面打磨：线条图标、金额字重、精简说明」两个 PR 关闭时没有合并。
- **建议：你决定要不要重启。** 要的话先发预览包给你看。

## 三、底层代码与架构

### 12. 先在真机量保存后的重建时间

- **现在**：手机每保存一笔都会重新解析整本账本。云端用 6 万笔样本测过，门槛已收紧，但不知道你实际的账本在真机上要多久。
- **做法**：在你的手机上看 `SaveTiming` 的数字，不读私人账本内容，只看耗时。
- **决定**：超过约 0.3 秒才值得做「只重新解析改动的文件」。那是大工程：余额、持仓这类跨文件结果仍要全量重算。
- **建议：先测量，再决定。**

### 13. 开发手册补 Mac

- **现在**：
  - 00 项目概况只写了 iOS。
  - 03 里 Mac 的全部说明挤在一个表格格子里，约三千字，人和智能体都难读、难改。
  - 06 没有 Mac 验收清单。
- **做了以后**：Mac 有独立小节，按页面列不变量；06 加 Mac 验收步骤。
- 工作量：小。风险：无（只改文档）。
- **建议：做**，最好和第 9 条一起。

### 14. 给 Mac 加最少量的界面测试

- **现在**：Mac 只有 LedgerKit 的逻辑测试和编译检查。打开账本、记一笔、撤销、换语言这些界面流程全靠人工验收。
- **做了以后**：云端自动跑几条 Mac 冒烟测试：打开虚构账本 → 记一笔 → 撤销 → 切英文。改坏了在合并前就能发现。
- 工作量：中。风险：低。会增加云端时间，约几分钟。
- **建议：做**，排在第 9 条之后。

### 15. 把取价和导入的平台无关部分移进 LedgerKit

- **现在**：联网取价（`Ledger/Sync/PriceFetch.swift`）等逻辑放在手机端，Mac 用不了。
- **做了以后**：用户看不到变化，但第 4、5 条可以直接复用，两端算法一致。
- 工作量：小到中。风险：低（只搬家，配测试）。
- **建议：做第 4、5 条时一起做**，不单独做。

### 不建议现在做

- **拆大文件**：`Store.swift`、`QuickAddView.swift` 等单文件 1100–1700 行。没有实际问题时成批拆分违反「只做实际需要的改动」，改到哪个再顺手整理。
- **两端共用界面代码**：03 已决定 Mac 和手机界面分开写，目前没发现两端配色或尺寸实际不一致；共用 SwiftUI 代码会让两边互相牵制。

## 四、测试与发布流程

### 16. 界面测试变慢、变脆

- **现在**：
  - 转正前全量的交互测试，预计约 20 分钟，最近一次跑了 79 分钟。
  - 月历滚轮测试两天里因时序修了 4 次。
  - 慢机器上读一次界面元素就要约 4 秒。
- **做了以后**：每次全量报告最慢的 10 个界面测试及耗时；能用 LedgerKit 测的逻辑从界面测试挪下去；剩下的界面测试只验证必须看界面的部分。转正更快，也不再被偶发的超时卡住。
- 工作量：中。风险：低。
- **建议：做。** 先加耗时报告（小），再按报告逐个处理。

### 17. 失败运行的证据自动清理

- **现在**：失败运行的日志、截图、录屏会在云端留 7–30 天。问题修好以后这些就没用了，这次手动清掉了约 3 GB。
- **做了以后**：发布成功后，自动删掉已被这一版取代的失败证据；运行记录和 PR 测试记录照常保留。
- 工作量：小。风险：低，删前核对没有还开着的 PR。
- **建议：可选。**

# 04 云端测试与发布

## 日常操作

| 入口 | 怎么运行 | 做什么 |
| --- | --- | --- |
| **Ledger CI** | 提交 PR 后自动运行 | 按 PR 改动检查；gate 通过才能合并，不发布 |
| **Ledger Dev** | Actions → Ledger Dev → Run workflow，Branch 选 **main** | 自动跑相关核心/存储测试、本次回归和少量关键界面流程，通过后打包开发版 |
| **Ledger Release** | 手机验收后运行，Branch 选 **main**，只填 `accepted_build` | 对已验收包的同一源码补齐全量，通过后将原 IPA 转正 |

Dev 没有输入参数。版本、构建号、源码提交、校验值和任务编号由程序获取。Release 的 `accepted_build` 填安装并验收那一包发布说明中的「构建 N」，只填 N，例如 `123`；不能拿最新开发版编号代替已安装编号。App「关于」目前只显示版本号。

CI（Continuous Integration，持续集成）检查、开发版可安装、手机验收、正式版发布是不同结果，分别记录。未验收写「待手机验收」。普通推送和 PR 不会自动发布。

## CI：合并前检查

每个面向 main 的 PR 都跑 `Ledger CI / gate`，不按路径跳过任务。它先实际加载共用发布组件，再运行静态检查、工具测试，以及 `tools/pr_scope.py` 选出的检查：

| 改动 | 检查 |
| --- | --- |
| 文档、工具 | 静态和工具测试，不编译 App |
| LedgerKit 源码 | 已核对依赖的 Search.swift 跑 SearchTests；其余源码仍跑全部核心测试 |
| 个别核心测试文件 | 对应测试类 |
| App、工程、本地化文件 | 没有待执行的 App 测试时只编译 App，不编译测试包 |
| App 内或界面测试 | 只编译所选测试目标及 App；同时涉及两层时保留两个测试包 |
| App 内或界面测试文件 | 运行 diff 影响的用例；共用辅助函数变化包含调用者，类外变化跑整个类 |

只有月历测试受影响时，还包含同文件其余月历测试。**只改 App 源码不会自动找到其全部关联界面测试**；CI 的当前规则不等于业务依赖分析，也不代替正式版前全量。

PR gate 只读，不用编译缓存，不上传产物、不发布。同一 PR 新提交取消旧检查。任务总时限 60 分钟；核心、编译、界面阶段分别最多 12、20、25 分钟，单项界面用例最多 180 秒。

Dev 与指定测试按目标选择 scheme：只选 `LedgerTests` 用 `LedgerHostedTests`，只选 `LedgerUITests` 用同名 scheme，同时选两层用 `LedgerInteractionTests`。每个被选中的 bundle 仍编译其全部测试文件；SwiftPM 的 `--filter` 也只减少执行用例，不减少测试 target 内源码编译。全量继续使用含两个 bundle 的 scheme。AppearanceTests 之前超时的长链表达式已在基线改为循环，此次不改 Swift 断言。

main 的保护规则应要求 PR 和 `gate` 检查通过。配置入口：Settings → Rules → Rulesets（或 Branches）→ main → Require a pull request / Require status checks。实际检查名以 PR Checks 为准；任务名保持 `gate`。

## Dev：少量、明确、可追踪

```sh
python3 tools/ship.py dev
```

只在干净、已同步的 main 上发起。比较**上次开发版到本次 main 的全部净改动**，覆盖多个 PR、删除和重命名，不只看最后一个提交。基线来自开发版清单，并核对 dev 标签；读取失败、身份不符或网络错误时停止。

测试选择由 `tools/dev_scope.py` 决定：

- 有明确对应关系的功能，跑对应核心/存储测试和界面用例。例如月历覆盖明细、订阅、字号与窄屏；演示加载只加演示仓库和加载隔离测试。
- 本次修改过的测试按 diff 选回归，不因测试类很大就自动跑整类；确实改到全类共用代码时仍按影响范围执行。
- App 代码变化另跑三个关键流程：已有交易无损编辑、快捷/完整表单共享金额、空表单关闭。
- 只改 `en.json` 或三个系统字符串目录（`Localizable`、`AppShortcuts`、`InfoPlist.xcstrings`）时，静态校验翻译与系统文案，开发版照常编译 IPA；以前附带的三个表单流程不再运行。其他资源仍保守处理；Swift 文件中的文案变化不按纯本地化文件处理。混合改动取各文件所需测试的并集。
- 未映射的 App 页面或工程配置只加编译和关键流程，**不因此启动整套界面测试**。未知核心改动可扩大到核心模块；未知存储改动可扩大到 App 内模块。首次或非祖先基线按当前源码功能选测。
- 界面映射失效时停止并修正，不用整套界面测试兜底。App 内模块若需要扩大，必须有实际可执行的测试，不能把零项算通过。
- 只改文档和发布工具时做静态、工具检查；生成开发版仍需编译 Release IPA。

这是一轮开发回归，不代表跨功能完整覆盖。完整界面、独立 Beancount 报表对照和全部模块在转正前验证。Dev 不接受 `--full`，不生成可用于转正的全量证据。

执行前，日志和 Actions Summary 列出基线、改动文件、所选用例及原因，另保存 `.ship/dev-test-plan.json`。Dev 实时输出编译、当前用例和失败日志，各阶段有独立时限：

| 阶段 | 上限 |
| --- | --- |
| 静态检查、工具测试 | 各 5 分钟 |
| 核心测试 | 12 分钟 |
| App 测试包编译 | 20 分钟 |
| 相关 App 内与界面测试 | 每轮 25 分钟，单项 180 秒 |
| Release IPA 编译 | 20 分钟 |

超时就失败，不发布；时限不是正常耗时承诺。普通和窄屏测试都要实际通过，分别保留日志、结果包和截图。发布说明写明实际范围，Dev 记录为 `scope=build`。

相关测试通过后，流程依次检查开发中版本 → 计算构建号 → 编译 IPA 并内置固定演示 → 校验版本、签名资源、ZIP、演示内容与 SHA256 → 核对源码仍是最新 main → 发布开发版 → 更新安装源。任一步失败停止后续。

## Release：验收原包转正

1. 安装开发版，记下其构建号，按 [06 手机验收清单](06-手机验收清单.md) 验收。
2. 验收后执行，或明确授权执行：

```sh
python3 tools/ship.py release --accepted-build 123
```

程序绑定构建号与 IPA SHA256，核对包、源码、文件树和固定演示快照。当前开发版已被其他构建替换时拒绝转正。

全量记录必须绑定已验收包的同一源码、文件树和演示内容。已有有效记录就复用；缺少时在独立工作区检出**安装包对应提交**补跑，不能改测更新的 main。全量包括静态、工具、全部核心测试、Beancount 报表对照、全部 LedgerTests 和 LedgerUITests。两个 App 测试目标都必须有非零通过数；失败、跳过、漏跑、零项或结果不可读都不算通过。全量单项界面用例时限为 300 秒。

通过后发布**同一个 IPA**，不重新编译，不改版本号或构建号。没有手机验收不能转正；任何检查失败或中断都不发布。

## 单独验证

Ledger CI 也可手动运行：Branch 选待测分支，源码号和机型通常留空。`core_filter`、`ui_tests` 都留空是全量，填写后只跑指定测试。需要手填时，应给出可直接复制的测试值。

```sh
# 指定核心回归；不编译 App、不发布
python3 tools/ship.py test --core-filter 'CalendarMarkTests|PostingOrderTests'

# 指定 App 内/界面用例，可重复 --ui-test
python3 tools/ship.py test --ui-test LedgerUITests/EditInteractionTests/testGlassCalendarFixedRowsAndDaySelection

# 窄屏；指定机型不可用时报错，不换成宽屏
python3 tools/ship.py test --device 'iPhone SE (3rd generation)' --ui-test LedgerUITests/EditInteractionTests/testGlassCalendarFixedRowsAndDaySelection

# 完整验证，只测试、不发布
python3 tools/ship.py test --full
```

`--ui-test` 格式是 `Target/Class[/method]`。指定测试必须实际执行，核对通过数和每个选择器；不能用空结果冒充通过。非 main 分支在网页选择，只能验证；本机发布客户端仍要求 main。

## 查看进度、失败与重试

```sh
python3 tools/ship.py watch --once
python3 tools/ship.py watch
```

- `queued` 是等待执行机，`pending` 可能在等发布锁，不是测试失败。`in_progress` 也不代表已经通过。
- Dev 日志实时显示进度；原有手动验证与正式版全量流程保留各自日志。阶段状态在 `.ship/status.json`，客户端任务链接在 `.ship/cloud.json`。
- 失败后查看首个失败阶段、日志和 `.xcresult`。测试尚未开始的模拟器环境失败可重跑；业务失败要修原因，不删测试、不放宽断言、不反复重跑凑绿。
- 源码已合并但未产出包，写「源码已在 main，未发布安装包」。发布或安装源更新中途失败，要核实实际远端状态，不能一律写成没有发布。
- 修复代码后从 Run workflow **新建任务**；旧任务 Re-run 仍使用旧提交。
- 正在发布的任务不擅自取消；Dev 与 Release 共用发布锁，排队只保留最新任务。旧源码不能覆盖新开发版。取消或中断不算通过。

日志、截图、结果包及已产生的 IPA 副本保留 7 天，全量证据保留 30 天。超时或外部取消可能来不及上传全部证据。GitHub Release 上的 IPA 长期保留，不删除 Release、标签或分支，不强推 main。

## 版本、安装源与环境

- 新版本用 `python3 tools/ship.py version patch|minor|major|X.Y.Z`，必须提高版本，在 CHANGELOG 顶部开始「开发中」一节。每项改动累加更新记录；发布说明自动生成。
- Dev 构建号取 Release 说明与 ipa 分支安装源历史中的最大值加一；历史不完整或无法解析时停止。正式版沿用验收包的同一个号。
- 转正后，将 CHANGELOG 标题改成北京时间发布日期，单独提交；下一项改动开始新版本。
- 安装源位于 ipa 分支：`dev.json`、`release.json` 和对应 `mirror/` 文件。安装工具使用用户自己的 Apple ID 签名，镜像由 gh-proxy.com 转发。
- 测试、模拟器、编译、打包和发布都在 GitHub 托管 `macos-26` 执行，Xcode 固定 26.6。Python 3.12、Beancount 3.2.0，已有 XcodeGen 不主动升级。本机只编辑、静态/工具检查、提交和发起云端任务。
- 只读取固定提交的公开演示库；测试和包内演示必须核对内容摘要，不读取私人账本。
- 缓存只用于依赖和测试编译产物；IPA 每次干净编译。缓存键以前只含工程配置，命中后不会更新；现在按源码摘要保存新缓存，只在系统、CPU 架构、Xcode 26.6、epoch、Package.swift、project.yml 和 Xcode 选择脚本相同的前缀下回退复用。配置、工具链或 epoch 变化即失效；源码变化仍执行编译命令，由编译器判断哪些产物可复用。测试每次实际运行，缓存不含结果包、验证证据或 IPA，不能凭命中认定通过。确认缓存损坏时才增大仓库 Actions Variable `LEDGER_CACHE_EPOCH`（默认 1）；日常不用填写，工作流解析后经输入传入共用组件。
- PR gate 只读；手动 CI 可保存缓存和证据；只有 Dev/Release 有发布权限。共用组件的内部 `check_only` 仅用于 PR 实际加载检查，不执行测试、打包或上传。

源码入口：工作流在 `.github/workflows/`，共用步骤在 `.github/actions/ledger-run/`，本机派发为 `tools/cloud.py`，云端入口为 `tools/cloud_worker.py`，执行逻辑为 `tools/ship.py`。

## 本地目录保持精简

- 本机不编译 App、不跑 Swift 测试或模拟器。轻量 Python 检查使用 `PYTHONDONTWRITEBYTECODE=1`，日志和一次性检查副本放系统临时目录，结束后清理本次产生的文件。
- 旧的 `build/`、`build-demo/`、`LedgerKit/.build/`、`dist/`、`Payload/`、`*.xcresult`、`*.log`、生成的 `Ledger.xcodeproj/`、`samples/` 和 Python 字节码都属于可重建产物，任务结束及时清理，不留在项目里长期堆积。
- 删除前核对目录与 Git 跟踪状态。保留源码、冻结样本、文档素材、任务记录及用户未提交改动，不使用不分对象的 `git clean -fdx`。清理只影响本地生成物，不能删除远端 Release、标签或分支。
- 清理后核对项目大小和 Git 状态。仍被进程使用或未能删除的文件如实列出，不能写成已经清空。
